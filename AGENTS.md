# Правила для агентов (dtz.html)

`dtz.html` — одностраничный тренажёр немецкой лексики (DTZ / B1–B2, B2 Beruf) без сборки и зависимостей. Весь словарь лежит прямо в файле, в шаблонных строках `const RAW_… = \`…\``.

## Формат данных

| Блок | Формат строки | Категория |
|---|---|---|
| `RAW_DER*`, `RAW_DAS*`, `RAW_DIE*` | `Wort|перевод` | `noun` (артикль задаётся блоком) |
| `RAW_VERB*` | `Verb|перевод` или `Verb|перевод|Dat.` / `Dat.+Akk.` | `verb` |
| `RAW_ADJ*` | `Adjektiv|перевод` | `adj` |
| `RAW_PREP*` | `Präposition|перевод|Akk.` / `Dat.` / `Gen.` / `Akk./Dat.` … | `prep` |
| `RAW_FRAGE`, `RAW_OTHER*` | `Wort|перевод` | `frage`, `other` |
| `RAW_PHRASE` | `Wendung|перевод` | `phrase` |
| `RAW_VERBPREP` | `Verb|Präposition|Akk.|перевод` | `verbprep` |
| `RAW_ORDER` | `токены через пробел|ложные,токены|перевод|Präsens/Perfekt|Aussage/Frage` | `order` |

## Переводы на языки интерфейса

Языки интерфейса: ru, uk, en, fr, it, fa, ar (fa и ar — справа налево, `dir="rtl"`). Поле перевода в `RAW_…` — **русское**; переводы на en/fr/it/fa/ar лежат в `RAW_I18N`: строка `ключ|en|fr|it|fa|ar`, ключ — `cat:article:Wort` (например `noun:der:Tisch`, `verb::gehen`), `vp:Verb:Präp:Kasus` для `RAW_VERBPREP`, `order:токены через пробел` для `RAW_ORDER`. Показ — через `trOf(w)`; если перевода нет, показывается русский (это ошибка, её надо исправить). Украинский интерфейс использует русские переводы слов.

- **Каждое новое слово** добавляется сразу и в свой `RAW_…` блок, и строкой в `RAW_I18N` на все 5 языков. Исправили слово/перевод — поправить и `RAW_I18N` (ключ зависит от немецкого слова и артикля).
- Внутри одной категории переводы на каждом языке тоже должны различаться (правило 6 действует для всех языков).
- В переводах нет символа `|`, нет кириллицы; fa/ar — арабской графикой.
- Новые строки интерфейса — в `STRINGS` для **всех 7 языков**; для статичной разметки — `setText(...)` в `applyI18nToStaticEls`.
- Смена языка всегда подтверждается окном «Язык: …» (на выбранном языке и на текущем).

## Стабильность прогресса — главное техническое правило

ID слов вычисляются по позиции: `"w"+индекс` по всем блокам в порядке `parseBlock(...)`, а у `RAW_VERBPREP` и `RAW_ORDER` — по индексу строки. Прогресс пользователей хранится по этим ID в `localStorage`.

- **Никогда не вставлять и не удалять строки в середине существующих блоков**, не менять порядок блоков в `baseWords`.
- Новые слова: дописывать **в конец** `RAW_VERBPREP` / `RAW_ORDER` или создавать **новый блок** и подключать его **последним** в `baseWords`.
- Исправление слова — замена строки **на том же месте**. Если слово нужно убрать, заменить его другим словом той же категории (и того же артикля для существительных).
- Новые поля в сохранении — с безопасным значением по умолчанию в `applyProgressData` (у старых пользователей поля нет).

## Лингвистические правила

1. **Немецкая сторона — только латиница** (с ä ö ü ß), правильная орфография по действующим правилам: `Straße`, `wie viel`, `naheliegend`. Никакой кириллицы.
2. **Перевод — только на русском и без немецких слов**: перевод показывается как вопрос в режиме RU→DE и не должен выдавать ответ (не `«Начальник (der Vorgesetzte)»`, не `«sich ~ …»`; пишем `«(возвр.) …»`).
3. **Артикль проверять по словарю (Duden).** Не придумывать род. Пример ошибки: «der Bank» не существует — *die Bank* = банк (мн. Banken) и скамейка (мн. Bänke).
4. **Слова, у которых значение зависит от рода** (der/die See, der/die Leiter, der/das Teil, der/das/die Band, der/das Schild, das/die Steuer, der/das Gehalt, der/die Kiefer, der/das Tor, der/das Erbe …), заносятся отдельными записями в соответствующие блоки артикля, каждая со своим переводом. Квиз сам ставит «пару» в варианты ответа.
5. **Только единственное число в блоках существительных.** Тренажёр «Артикль: падежи» склоняет артикль по роду; слова *pluralia tantum* (Kosten, Daten, Leute, Eltern, Papiere …) ломают его — их не добавлять в блоки существительных (можно во фразы).
6. **Переводы должны различаться.** Если у двух слов одной категории одинаковый перевод, квиз не сможет поставить их рядом, а в RU→DE ответ неоднозначен. Уточнять: `kennen — знать (быть знакомым)` / `wissen — знать (факт)`, `buchen — бронировать (поездку)` / `reservieren — резервировать (столик)`.
7. **Падеж/управление** указывать точно: глаголы с дательным — `|Dat.`, с дательным и винительным — `|Dat.+Akk.`; у предлогов — падеж(и) по грамматике; в `RAW_VERBPREP` — падеж, которым управляет предлог в этом сочетании.
8. **Нет дублей** внутри категории (одно и то же слово с тем же артиклем). Перед добавлением — проверить существующие блоки.
9. Уровень и тематика — то, что реально нужно для DTZ/B1–B2 и работы в Германии; помечать стиль, где важно: `(разг.)`, `(книжн.)`, `(офиц.)`, `(старое название)`.

## Квиз и интерфейс

- Направления: `ru-de`, `de-ru`, `random` (`quizDir`). В режиме DE→RU показывается немецкое слово, варианты — переводы; в RU→DE — наоборот. `case` и `order` не зависят от направления; `verbprep` в RU→DE — выбор предлога.
- Варианты ответа: всегда 5, без вариантов с тем же переводом; для маленьких разделов добираются из базового словаря (`distractorPool`).
- Ответ всегда выбирается и затем подтверждается кнопкой «Подтвердить» (в том же блоке под вариантами) — независимо от озвучки и направления.
- Озвучка (SpeechSynthesis, `de-DE`) произносит только немецкий текст; по умолчанию выключена.
- Свои слова пользователя: `customWords[deckId]`, для базовой сборки — `customWords["basic"]`. Форма не даёт сохранить немецкое слово кириллицей.
- Тексты интерфейса — в `STRINGS` на семи языках (ru, uk, en, fr, it, fa, ar); новые ключи добавлять во все.
- Темы: палитры — CSS-переменные в `[data-theme="…"]`, список — `THEME_OPTIONS`. `dark` = «Обычная» (по умолчанию). Новая тема: задать **все** переменные палитры и добавить в `THEME_OPTIONS`.
- Окна первого запуска/«что нового» идут цепочкой через `startOnboarding()`: шаги `lang`, `theme`, `dir`, `support`, у каждого — флаг в сохранении (`onboarded`, `themeAsked`, `dirAsked`). Если шагов больше одного, сверху показывается «Шаг N из M» и «Пропустить всё». Новое одноразовое окно — добавить шаг в очередь, а не открывать модалку напрямую.
- Удобства обучения: «Не знаю» (засчитывается как ошибка и показывает ответ), «Повторить ошибки» (`mistakes`, режим `mistakeMode`; слово уходит из списка после верного ответа), цель на день `dailyGoal` (10/20/30/50/0) и серия дней `dayStreak`, 🔊 на карточке и в списке слов (`speakNow`, работает и при выключенной автоозвучке), клавиатура: 1–5, Enter (подтвердить / пропустить паузу), Backspace в «Порядке слов». Переход к следующему вопросу — только через `scheduleNext()`.
- Свои разделы можно удалить (🗑 в «Разделах»); базовый словарь удалить нельзя.

## Проверка перед коммитом

1. Скрипт-аудит: в немецкой стороне нет кириллицы, в переводе нет латиницы, нет дублей внутри блока; у каждой записи есть строка в `RAW_I18N` со всеми 5 языками.
2. Открыть страницу в Playwright (Chromium уже установлен), убедиться, что нет ошибок в консоли, пройти несколько вопросов в каждом направлении.
3. Сообщение коммита — короткое, без упоминания авторства ИИ-инструментов. Пушить в `main`.

# Правила для агентов (moqup/)

`moqup/` — генератор кликабельных прототипов админок из JSON (для презентаций: логистика, WWS/WMS, CRM, ERP, маркетинг, продажи, бухгалтерия). Без сборки и зависимостей.

| Файл | Что там |
|---|---|
| `moqup/dashboard.html` | разметка + **все стили** (палитра — CSS-переменные в `:root` и `[data-mode=light]`) |
| `moqup/helper.js` | движок: чтение параметров `map`/`colors`/`demo`/`logo`/`page` (из `?` и `#`), декодирование (`z:` deflate-raw, `pako:` zlib, `b64:`, JSON), проверка с понятными ошибками, экран документации и конструктор ссылки, загрузчик со счётчиком, каркас, виджеты (`WIDGETS.<type>`), действия (`runAction`), AI-чат, демо-курсор, финал |
| `moqup/examples.js` | `window.MOQUP_EXAMPLES` — эталонные конфигурации (`map` + `colors` + `demo` + `logo`) |
| `moqup/DOCS.md` | **единственный источник правды по формату JSON** + промпт для ИИ |

Правила:

- Новый тип виджета: функция `WIDGETS.<type> = w => element`, ширина по умолчанию в `DEFAULT_W`, синонимы в `ALIASES`, вложенные виджеты — в `CONTAINERS`; интерактивным элементам давать `ref` (`data-ref`) для целей демо; описать в `DOCS.md` (каталог виджетов и таблица целей).
- Новое действие — в `runAction` и таблицу действий в `DOCS.md`; новый шаг демо — в `doStep` и раздел «Демо».
- Пользовательский текст выводить только через `textContent` (`h(..., {text})`) или `md()` (экранирует); `innerHTML` — только для своей разметки. Цвета из JSON — только через `cssColor()`/`validColor()`, URL — через `safeUrl()`, логотип SVG — только как `<img>`.
- Тексты интерфейса — в `I18N` для `ru`, `en`, `de`.
- Ошибка в одном виджете не должна ронять страницу: предупреждение через `warn()` (значок ⚠ в топбаре).
- Изменили формат — обновить `DOCS.md`, при необходимости `examples.js` и краткое описание в `README.md`.

Проверка перед коммитом: `node --check moqup/helper.js moqup/examples.js`; открыть `moqup/dashboard.html` через http-сервер в Playwright: без параметров (документация), со сломанным JSON (ошибка), оба примера (нет ошибок в консоли, все разделы открываются), прогнать демо до финала, проверить ширину телефона (iPhone 13).
